AVANCE VERIFICADO

Avance 1 · La conversación ahora es una entidad del sistema

Limitación inicial

Gradio mostraba mensajes, pero el backend trataba cada envío como una consulta independiente. No existían usuario, conversación activa ni continuidad recuperable.

Implementación

Se añadieron ConversationRepository, ConversationMemory, identificadores UUID, persistencia de mensajes, título automático, problema activo, resumen y reapertura desde SQLite.

Evidencia del avance

Una respuesta breve conserva el ejercicio; cerrar y abrir la interfaz no borra turnos; cada usuario lista únicamente sus conversaciones.

ANTES: question → retriever → LLM → respuesta efímera
AHORA: user_id + conversation_id + history → contextualize → retriever → LLM → persist turn
Valor doctoral: habilita experimentos multi-turno y análisis longitudinal; antes sólo era posible evaluar preguntas aisladas.

AVANCE VERIFICADO

Avance 4 · Autenticación seudónima y aislamiento

Problema resuelto

El ID escrito libremente permitía intentar cargar conversaciones ajenas. Tampoco existía distinción entre estudiante e investigador.

Implementación

Registro/login con PIN protegido mediante PBKDF2‑HMAC‑SHA256 (310.000 iteraciones), sal aleatoria de 16 bytes, comparación constante y token de sesión aleatorio.

Comprobación

Los tests rechazan PIN incorrecto, sesión revocada, conversación de otro usuario y operaciones de investigador desde rol student.

Credenciales→hash(PIN,salt)→compare_digest→session token→AUTH.require
Autorización de conversación = sesión válida ∧ session.user_id = conversation.user_id
Rol investigador = user_id preautorizado; nunca seleccionado libremente en la UI
La interfaz inicia con 25 controles bloqueados; sólo un login válido habilita chat, comparación, perfil e investigación.
Continuidad pedagógica multi-turno
AVANCE VERIFICADO

Avance 5 · Memoria activa con dos canales de contexto

Problema resuelto

Respuestas como “3”, “sí”, “¿por qué?” o “ese paso” no eran consultas recuperables por sí solas.

Implementación

Se construyen por separado retrieval_query y conversation_context. El primero recupera evidencia; el segundo mantiene el diálogo del generador.

Límites controlados

8 mensajes recientes; resumen desde 12; máximo 1.600 caracteres; problema activo hasta 500 caracteres.

Canal A · Retriever

q* = contextualize(qₜ, history)
retrieve(q*, top_k=5)

La query autónoma entra igual a dense, BM25, Graph‑RAG, SA o v3.

Canal B · Generador

Cₜ = summary + active_problem
+ last_8_messages

El LLM recibe Cₜ, pregunta actual, evidencia y el mismo prompt pedagógico.

Ejemplo validado: “x = 3” recupera junto con “f(x)=1/(x−3)” sin otra llamada al LLM.
Gestión explícita del ciclo conversacional
CORRECCIÓN IMPLEMENTADA

Avance 6 · “Limpiar” ahora significa conversación nueva

Defecto observado

Se vaciaba el componente visual, pero se conservaba el UUID. La siguiente pregunta reconstruía la conversación anterior desde SQLite.

Cambio realizado

ClearButton fue reemplazado por un callback autenticado que ejecuta create_conversation(), devuelve el nuevo UUID y actualiza chat y selector.

Decisión de datos

No se borra la conversación anterior: permanece disponible para análisis longitudinal, auditoría y reapertura.

click clear→AUTH.require→INSERT conversations→conv_UUID₂→history=[]
assert UUID₂ ≠ UUID₁
assert prepare(UUID₂,"¿y ahora?") no contiene active_problem(UUID₁)
Nueva prueba unitaria: el contexto del problema anterior no atraviesa la frontera de conversación.

Asociación conceptual

Usa concepts de la metadata de la última respuesta del tutor; si faltan, usa los conceptos recuperados actualmente.

Extractor

Reglas auditables detectan comprensión, parcialidad, confusión y ayuda; guardan el mensaje y la versión del extractor.

Control de error

Una respuesta matemática no se considera correcta sin gold verificable; queda como observación no calificada.

Sin botones, el lenguaje explícito del estudiante ya actualiza el perfil; la inferencia pesa cuatro veces menos que el feedback directo.
